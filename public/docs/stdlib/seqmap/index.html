Types

SeqMap

type SeqMap k v (h = _) =
    hasher: Hash k h
    log_len: U32
    count: U32
    data: Ptr (Data k v)

A persistent hash map based on Seq. Performance is meant to be comparable to a mutable HashMap.

Common operations:

  • insert, remove, get: O(1) amortized but can be O(N) with worst-case sharing patterns.
  • clone: O(1)

Internally, a SeqMap is a Seq-like append-only log of entries. Inserts and removes are each recorded by adding an event to the end of the log.

Each SeqMap remembers how much of the log it can see, which lets many SeqMaps share the same log. Each SeqMap never reads past its own length, so a newer SeqMap can keep adding to the shared log without disturbing any older ones. An older SeqMap simply skips any versions of a key which were added after it.

A write only needs to copy when the log is out of room, or when the SeqMap being written to would overwrite later entries already used by other SeqMaps. In the second case its entries are compacted into a new log of its own.

This can be exploited to force an O(N) copy on every write by cloning at every step and writing to both the original and the clone:

var map = empty ()
while true do
    other = clone map      // map and other now share the same log
    map := insert map 0 0  // add to the end of the shared log
    insert other 0 1       // other is now behind the end of the log, forcing a copy

This scenario should be rare. A more common usage would be for each clone to be a snapshot of the map at a point in time, in which case writes to the original remain O(1) amortized. If you need a persistent map type, SeqMap should still be a good default, but always benchmark if performance is important.

Note that SeqMap is not thread-safe

insert

insert (map: SeqMap k v h) (key: k) (value: v) {_: Eq k e} {_: Drop k d} {_: Drop v d}: SeqMap k v h can e, d

Insert a new key, value pair in the map. This will drop the previous entry of the same key only if no other shared map is still holding onto it.

Runs in roughly O(1) amortized time, though can be O(N) over the shared chain with worst-case sharing patterns.
